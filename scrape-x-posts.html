用 Monid 抓 X 推文：一条 $0.0004 的完整实操

2026-11-18 · 实测价格与命令

抓 X 数据最麻烦的不是解析，是拿不到：Guest API 限制多、登录态容易掉、IP 一换就验证。走 Apify 的 tweet-scraper 能绕开这些，但 Apify 自己的计费是按 run 算的，小批量用不划算。

Monid 把这层包了：按条计费，一条推文 $0.0004。一万条四美元。

第一步：确认接口还在、价格多少

monid discover -q "twitter tweets search" -l 5 -j

返回里会带每个接口的单价、健康度和调用方式。找 apify / apidojo/tweet-scraper，$0.0004/条。

第二步：读参数 schema，别猜

monid inspect -p apify -e /apidojo/tweet-scraper -j

这一步省时间的地方在于：它把 body、query、path 三块参数分开列出来。很多人直接照着 Apify 网页文档填参数，字段名对不上就报 400。

第三步：跑

monid run -p apify -e /apidojo/tweet-scraper \
  -i '{"searchTerms":["AI 中转站"],"maxItems":20}' -w -j

Apify 是异步的：提交后返回 202 和一个 runId。加 -w 让它帮你轮询到结果出来。

三个实际会遇到的坑

1. 拿到的条数不等于 maxItems。搜索结果去重、转推过滤之后会少。想要 50 条有效数据，maxItems 建议设 80。

2. 中文关键词的结果质量取决于输入写法。"AI 中转站" 能搜到，但 "AI中转" 和 "AI 中转" 是两个不同的查询。要覆盖全，就在 searchTerms 里放多个变体，一次请求跑完。

3. 余额是真的会扣。monid run 直接扣钱包，没有"沙盒模式"。先用 maxItems=5 试通，再放大。

成本怎么算

按条计费的好处是成本可预测：

每天抓 500 条 × $0.0004 = $0.2 / 天
一个月 15,000 条          = $6 / 月

同样的量走 Apify 自己的套餐，起充是 $49/月。这就是网关的价值——不为一周跑一次的任务付月费。

拿到数据之后

返回是结构化 JSON，直接进你的分析流程：监控竞品调价、统计某个话题的传播曲线、筛出有购买意向的账号做线索。我们自己的用法是每天跑一次关键词，把结果落到本地库里做趋势对比。
