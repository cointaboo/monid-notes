Monid 是什么：2800 个数据接口，一个钱包

2026-11-18 · 基于实际调用记录

如果你想抓 TikTok 的爆款视频、X 上的关键词推文、Amazon 的商品价格、或者找某个人的商务邮箱，通常有三条路：自己写爬虫、买某个平台单独的 API、或者一次性接一堆第三方服务。

Monid 是第四条：一个网关，把 2800 多个数据接口聚到一个 API key 和一个预付费钱包后面，按调用次数扣费。

它解决的具体问题

自己写爬虫的成本不在代码，在于维护：目标站改版、加验证码、封 IP，每一样都要人盯。买单个平台的 API 又会出现另一种麻烦——你有五个需求，就要注册五个平台、充五次钱、记五套鉴权。

Monid 把这些上游（Apify、TikHub、DataForSEO、Hunter.io、ContactOut、search1api 等）统一到一套接口后面。你只需要关心三件事：找到接口、读它的参数、调用它。

计费方式

没有订阅，按次扣费。不同接口价格差很多：

类型价格区间例子
按结果计费$0.0003 – 0.0026 / 条X 推文 $0.0004/条，TikTok 视频 $0.0003/条
按调用计费$0.001 – 0.01 / 次搜索趋势 $0.001，Amazon 商品 $0.0033
阶梯（人肉数据）$0.02 – 0.2 / 人LinkedIn 商务邮箱

注册送 $1 额度，够跑几百条推文做验证，这比先绑卡再试用友好。

三步接入

# 1. 找接口，带报价和健康度
monid discover -q "tiktok trending videos" -l 5 -j

# 2. 读参数 schema（别猜字段名）
monid inspect -p apify -e /apidojo/tweet-scraper -j

# 3. 真跑
monid run -p apify -e /apidojo/tweet-scraper \
  -i '{"searchTerms":["关键词"],"maxItems":10}' -w -j

-i 是 body，--query 是 query 参数，--path 是 path 参数——对应 inspect 返回的三块结构。-w 会自动轮询异步上游（比如 Apify 返回 202 + runId 的情况）。

它不做什么

这点很重要，能省你很多时间：Monid 没有 Telegram 数据接口。用 TG 相关关键词去搜，返回的是 Facebook / TikTok / X 的结果。如果你的需求是群成员、频道消息、协议号数据，这条路走不通，得自己解决。

另外，如果你已经有某个平台的专用账号和 key（比如官方的 DataForSEO 账户），直接用自己的更便宜，没必要过一层网关。

适合谁

适合的场景：需求会变、量不稳定、不想为每个数据源单独开户。比如做竞品价格监控、社媒选题、线索筛选——今天抓 X，下周抓 Amazon，用同一套鉴权和同一个钱包。

不适合的场景：单一数据源、超大流量、有长期合同价。那种情况直接找上游签更划算。
